# monitoring_two_persent

Бот для Bybit (USDT-перпетуалы, API V5). Следит за балансом счёта и, когда дневная прибыль
(с учётом комиссий, фандинга и издержек выхода) достигает цели (по умолчанию +2% от баланса на 00:00 МСК),
начинает **постепенно** закрывать позиции лимитными ордерами, подстраивая размер под стакан,
чтобы не двигать цену.

## Дневная цель (считается по торговому результату, а не по балансу)
* Каждый день в **00:00 по Москве** бот записывает **базу дня**: баланс счёта (это знаменатель процента) и
  нереализованный PnL открытых позиций на этот момент. При первом запуске — значения на момент старта; если бот был
  выключен в полночь — на момент следующего старта.
* Результат дня = **реализованный** (лог транзакций Bybit: сделки, комиссии, фандинг)
  + **изменение нереализованного** PnL с начала дня + **поправка на выход** (комиссия тейкер и проскальзывание при закрытии по стакану).
* **Запуск днём.** Бот берёт сделки с 00:00 из лога транзакций, восстанавливает базу на 00:00 (баланс сейчас − все изменения
  счёта за день, включая переводы) и сразу считает результат дня. Цель уже выполнена → она записывается в БД. Нереализованный PnL
  позиций, открытых в момент старта, на 00:00 неизвестен — для них считается только дальнейшее изменение.
* **Цель проверяется перед каждым куском закрытия.** Результат дня пересчитывается заново (лог транзакций + позиции +
  стоимость выхода) перед каждой лимиткой на закрытие. Если он опустился ниже цели, закрытие **останавливается**, отметка
  «цель выполнена» снимается, и бот снова просто следит; как только результат снова ≥ цели — отметка ставится заново и
  закрытие продолжается. Если позиций нет, результат тоже перепроверяется каждый шаг: упал ниже цели — отметка снимается
  (иначе копия никогда не вернулась бы к копированию). Нет данных лога транзакций → новый кусок не ставится.
* **Пополнения, выводы, переводы между аккаунтами и изменение цены обеспечения (BTC и пр.) на цель не влияют** —
  баланс в расчёте не участвует (в логе показывается только справочно). В лог транзакций берутся типы
  `TRADE, SETTLEMENT (фандинг), DELIVERY, LIQUIDATION, ADL, FEE_REFUND, INTEREST`; `TRANSFER_*`, бонусы, конвертации, Earn исключены.
  Эндпоинт — `/v5/account/transaction-log` (категория `linear`, валюта `SETTLE_COIN`); нужны права чтения ордеров/позиций/счёта.
* Результат ≥ `TARGET_PROFIT_PCT` (по умолчанию 2% от базы) → в БД пишется «цель выполнена», бот закрывает позиции кусками
  (каждый раз проверяя, что результат всё ещё ≥ цели) и закрывает новые позиции, пока результат не ниже цели. В 00:00 день сбрасывается.
* Итог дня (результат в USDT и баланс после закрытия) тоже записывается.
* Нет данных лога транзакций → цель не засчитывается (бот ждёт); если цель уже достигнута — закрытие продолжается.

## Копирование на другие счета
Основной счёт (ключи в `.env`) — ведущий. Остальные счета повторяют его позиции пропорционально equity:
нужный размер = размер на основном × (баланс копии / баланс основного) × `multiplier`. Баланс берётся **без нереализованного PnL**
(equity − UPL): иначе пропорция «плыла» вместе с ценой, и копия то докупала, то сбрасывала позицию. Пропорция меняется, только
если ушла больше чем на 2% (гистерезис).
Пример: основной 100 USDT, позиция на 10 USDT; копия 1000 USDT → на копии позиция на 100 USDT.

* **Список счетов** — файл `data/followers.json` (путь можно задать `FOLLOWERS_FILE`; пример — `followers.example.json`).
  Файл лежит в `data/`, в git не попадает. Добавить счёт = дописать запись (имя, `api_key`, `api_secret`) и перезапустить бота.
  Поле `dry_run: true` — копия только пишет в лог, что сделала бы. Начните с него.
* **Как входит.** Каждую секунду сверяется «нужно» и «есть». Добор идёт кусками: один `PostOnly`-лимит на позицию,
  размер = `BOOK_FRACTION` глубины стакана, цена — лучшая своей стороны (мейкер). Не исполнился за `ORDER_TIMEOUT_SEC` —
  отменяется и пересчитывается. Сокращения и закрытия основного счёта повторяются через `reduceOnly`.
  Расхождение меньше `COPY_DEADBAND_PCT` (3%) не трогается — чтобы не дёргать позицию из-за колебаний пропорции;
  пропорция пересчитывается раз в `COPY_RATIO_REFRESH_SEC` (60 с).
* **Плечо** на копии выставляется как на основном перед открытием (если не вышло — позиция не открывается).
  **Режим маржи и режим хеджа** — настройки всего аккаунта; бот только предупреждает в логе, если они отличаются.
* **Своя цель у каждой копии.** Копия считает результат дня от своей базы (отдельный файл
  `data/state_<имя>_<net>_<dry|live>.db`). Достигла +`TARGET_PROFIT_PCT` — закрывает всё и до 00:00 не копирует.
* **Копия — выделенный счёт.** Всё, чего нет на основном счёте, на копии будет закрыто.
* Если позиции основного счёта не удалось получить, копии ничего не делают; пустой ответ после непустого принимается
  только со второго раза подряд.
* Не реализовано: добор по рынку, если копия сильно отстаёт от основного.

### Веб-интерфейс настроек
Страница, где вводятся API Key / Secret основного счёта и список копирующих счетов (имя, ключи, множитель, dry-run,
включён/выключен, testnet), с кнопкой «Проверить» (запрашивает баланс) и «Сохранить». После «Сохранить» файл
`data/followers.json` записывается (права 0600) и бот перезапускается сам (Docker `restart: unless-stopped` / systemd).

* Включается, только если в `.env` задан `UI_PASSWORD`. Доступ — HTTP Basic, логин любой, пароль `UI_PASSWORD`.
* Порт открыт **только на localhost сервера** (HTTP без шифрования): заходите через SSH-туннель
  `ssh -L 8080:localhost:8080 root@<сервер>` и открывайте `http://localhost:8080`. В интернет порт не выставляйте.
* Секреты браузеру не возвращаются; пустое поле Secret при сохранении = «оставить прежний».
* Ключи основного счёта из интерфейса приоритетнее `.env`; если поле основного пустое — работает `.env`.
* Если ключей основного счёта нет вообще, бот стартует только с интерфейсом и ждёт, пока вы их сохраните.

## Файлы
* Состояние — один файл SQLite `data/state_<mainnet|testnet>_<dry|live>.db` (таблицы `days`, `events`).
  У DRY-RUN и боевого режима файлы разные: «цель выполнена» из теста не влияет на боевой режим.
* Логи — `logs/bot-YYYY-MM-DD.log`, по файлу на день (время московское). Файлы старше 7 дней (`LOG_RETENTION_DAYS`) удаляются
  при старте и при смене дня.
* Сбросить сегодняшний день (пересчитать базу и цель): остановите бота и выполните `./run.sh reset`.
* Посмотреть историю дней: `sqlite3 data/state_mainnet_live.db "select * from days"`.

## Как закрывает
* Ордер: `Limit`, `PostOnly`, `reduceOnly` — всегда мейкер и не может открыть/перевернуть позицию.
* Цена: лучшая цена своей стороны (лонг — best ask, шорт — best bid): встаём в очередь, стакан не съедаем.
* Размер куска = `BOOK_FRACTION` (10%) от ликвидности в пределах `BOOK_DEPTH_BPS` от лучшей цены,
  с учётом `qtyStep`/`minOrderQty`; «пыль» не оставляется.
* Не выставляет ордера при спреде шире `MAX_SPREAD_BPS`.
* Не исполнился за `ORDER_TIMEOUT_SEC` — отменяется, на следующем шаге всё пересчитывается по свежему стакану.
* За шаг — один кусок одной позиции (по кругу); перед каждым куском PnL пересчитывается.
  После достижения цели закрытие не приостанавливается, пока не закрыто всё.

## Запуск (на своём компьютере)
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # впишите ключи
python main.py --once     # один проход: только показать PnL
python main.py            # цикл, по умолчанию DRY_RUN=true (ордера НЕ отправляются)
python main.py --live     # боевой режим
pytest                    # тесты
```

**Рекомендуемый порядок:** `BYBIT_TESTNET=true` → DRY_RUN на реальном аккаунте (сверьте
процент в логе с интерфейсом Bybit) → `--live` на малой позиции.

API-ключ: только права на ордера/позиции деривативов, **без права вывода**, желательно с привязкой к IP.

## Допущения — проверьте
1. Unified Trading Account, USDT-перпетуалы (`linear`). Сверьте «результат дня» в логе с «PnL за сегодня» в интерфейсе Bybit.
2. Часовой пояс дня задаётся `TIMEZONE` (по умолчанию Europe/Moscow) и не зависит от настроек машины — безопасно для переезда на сервер.
3. На сервере: пути `DATA_DIR`/`LOG_DIR`, остановка по SIGTERM корректна; API-ключ привяжите к IP сервера.

Не является финансовой рекомендацией; вы отвечаете за торговые решения и риски.
