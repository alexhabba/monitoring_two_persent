# Как добавить ключи счетов

Ключи вводятся на веб-странице бота. Основной счёт — тот, что ведёт торговлю; копирующие счета повторяют его позиции
пропорционально размеру депозита. Подробности работы копирования — в [README.md](README.md).

> [!CAUTION]
> ## 🔴 ОБЯЗАТЕЛЬНО: режим маржи и режим позиции на копирующем счёте должны быть такими же, как на основном
>
> Бот **НЕ меняет** эти настройки сам (они относятся ко всему аккаунту Bybit) — он только пишет предупреждение в лог.
> Проверьте и выставьте вручную **до** включения копии (особенно до снятия галочки «Только лог»):
>
> | Настройка | Где в Bybit | Что должно совпадать |
> |---|---|---|
> | **Режим маржи** | Деривативы (Trade → USDT Perpetual) → значок настроек ⚙ → *Margin Mode* | Кросс (*Cross Margin*) / Изолированная (*Isolated*) / Портфельная — как на основном |
> | **Режим позиции** | там же → *Position Mode* | *One-Way* или *Hedge* — как на основном (для каждой монеты) |
>
> **Если не совпадают:** ордера могут отклоняться биржей (ошибка «position mode not match»), либо позиции откроются с другим риском
> (например, изолированная маржа вместо кросса — риск ликвидации выше). Плечо бот выставляет сам, а эти два режима — нет.
>
> Предупреждение в логе выглядит так: `Режим маржи копии (…) отличается от основного (…)`. Если видите его — исправьте
> настройку в Bybit. Проверить: `ssh root@81.163.28.80 "docker logs monitoring_two_persent 2>&1 | grep 'Режим маржи'"`.

## 1. Создайте API-ключ на Bybit (для каждого счёта)
1. Bybit → профиль → **API** → **Create New Key** → *System-generated API Keys*, тип **API Transaction**.
2. Права: **Contract / Derivatives → Orders и Positions** (+ чтение счёта, `Unified Trading → Trade`). **Вывод средств (Withdraw) не включать.**
3. **Привяжите IP сервера** `81.163.28.80` (поле *IP restriction*) — без привязки ключ живёт 3 месяца и менее безопасен;
   с привязкой — бессрочный.
4. Сохраните **API Key** и **API Secret**. Secret показывается один раз.

## 2. Откройте страницу настроек
Страница доступна только через SSH-туннель (наружу порт не открыт).

1. В терминале на Mac запустите туннель и **оставьте окно открытым**:
   ```bash
   ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=4 -N -L 8080:localhost:8080 root@81.163.28.80
   ```
   Терминал будет «висеть» без вывода — это нормально.
2. В браузере откройте `http://localhost:8080`.
3. Появится окно входа: **имя пользователя — любое** (например `admin`, оно не проверяется), **пароль — значение `UI_PASSWORD`**
   (см. ниже, где его посмотреть и как сменить).

### Где посмотреть пароль
Пароль хранится на сервере в файле `/opt/monitoring_two_persent/.env`, строка `UI_PASSWORD=…`:
```bash
ssh root@81.163.28.80 "grep UI_PASSWORD /opt/monitoring_two_persent/.env"
```
(В репозиторий и в эту инструкцию пароль не записывается.)

### Как сменить пароль
1. Впишите новый пароль (латиница и цифры, без пробелов и спецсимволов `& \ /` — так проще) вместо `НОВЫЙ_ПАРОЛЬ`:
   ```bash
   ssh root@81.163.28.80 "sed -i 's/^UI_PASSWORD=.*/UI_PASSWORD=НОВЫЙ_ПАРОЛЬ/' /opt/monitoring_two_persent/.env"
   ```
   Либо откройте файл вручную: `ssh root@81.163.28.80`, затем `nano /opt/monitoring_two_persent/.env` и поправьте строку `UI_PASSWORD=`.
2. Пересоздайте контейнер, чтобы он прочитал новый пароль (простой `restart` изменения `.env` **не подхватывает**):
   ```bash
   ssh root@81.163.28.80 "cd /opt/monitoring_two_persent && docker compose up -d --force-recreate"
   ```
   Бот перезапустится за несколько секунд (если открыта позиция — лучше делать это, когда позиций нет).
3. Закройте вкладку с настройками и откройте `http://localhost:8080` заново — браузер спросит новый пароль.

Если строки `UI_PASSWORD=` в `.env` нет или она пустая — веб-интерфейс **выключен** (страница не откроется). Добавьте пароль и
пересоздайте контейнер, как выше. Пароль должен быть длинным и случайным: страница защищена только им.

**Если страница не открывается или пишет «Failed to fetch»** — туннель не запущен или оборвался: запустите команду из п. 1 заново (страницу
перезагружать не нужно).

## 3. Добавьте копирующий счёт
1. Нажмите **«+ Добавить копирующий счёт»**.
2. **Сначала убедитесь, что режимы маржи и позиции на копии совпадают с основным (красный блок вверху).** Затем заполните карточку:

   | Поле | Что вписать |
   |---|---|
   | Имя | любое латиницей, цифры, `_` и `-` (например `acc2`) — по нему называется файл состояния и строки в логе |
   | API Key / API Secret | ключи **копирующего** счёта |
   | Множитель размера | `1` = строго по доле депозита; `0.5` — вдвое осторожнее; `2` — вдвое агрессивнее |
   | Включён | снимите, чтобы временно отключить копию, не удаляя ключи |
   | Только лог (dry-run) | **оставьте включённой на первый раз** — бот только пишет в лог, что поставил бы, ордера не шлёт |
   | Testnet | только для ключей тестовой сети Bybit |

3. Нажмите **«Проверить»** — при верных ключах покажет баланс копии; при ошибке — причину от Bybit.
4. Нажмите **«Сохранить»** (внизу). Файл записывается на сервере, бот сам перезапускается за несколько секунд.
5. Чтобы добавить ещё счета — повторите шаги 1–4 для каждого. Удалить счёт — кнопка **«Удалить»**, затем «Сохранить».

Секреты страница обратно не показывает: пустое поле Secret при сохранении означает «оставить прежний».

## 4. Проверьте, что ключ добавился
На сервере (в логе бота):
```bash
ssh root@81.163.28.80 "docker logs --since 10m monitoring_two_persent 2>&1 | grep -E 'Копирование|Пропорция|\[acc2\]'"
```
Должны быть строки «Копирование: N счетов (…)», «[имя] Пропорция: ×…». В dry-run, когда у основного есть позиции, появятся
строки `[имя] … [DRY-RUN]` с ордерами, которые бот поставил бы. Сохранённые записи (без секретов):
```bash
ssh root@81.163.28.80 "python3 -c \"import json;[print(f['name'],f['api_key'][:4]+'…',f['multiplier'],'dry' if f['dry_run'] else 'LIVE') for f in json.load(open('/opt/monitoring_two_persent/data/followers.json'))['followers']]\""
```

## 5. Включите боевой режим
Когда в логе всё выглядит правильно: снимите галочку **«Только лог»** у копии → **«Сохранить»**. С этого момента бот
реально ставит ордера на копирующем счёте. Начните с небольшой суммы на нём.

## Важно
* **Копирующий счёт должен быть выделенным.** Любая позиция на нём, которой нет на основном счёте, будет закрыта.
* **Поле «Основной счёт» оставляйте пустым**, пока бот должен работать с ключами из `.env`. Если вписать туда ключи и
  сохранить, основным станет этот счёт (ключи со страницы приоритетнее `.env`); дневная база при этом считается заново.
* 🔴 Режим маржи и режим позиции (One-Way/Hedge) на копии должны совпадать с основным — см. красный блок в начале файла.
  Бот их не меняет, только предупреждает в логе. Плечо бот выставляет сам.
* У каждой копии своя дневная цель (+`TARGET_PROFIT_PCT`, сейчас 4%): достигла — закрывает всё и до 00:00 не копирует.
* Ключи лежат на сервере в `data/followers.json` (права 0600), в git не попадают.
